1. Quick Start

$ pip install -e agent-harness/ # Install the CLI $ tradecraft --help # See all commands $ tradecraft health # Check backend is running $ tradecraft sectors list # See sector performance $ tradecraft strategy create "mean reversion on AAPL using RSI(30/70)" --tickers AAPL $ tradecraft coach kpis --period 30 # Check your trading KPIs

The CLI talks to a FastAPI backend (port 8000) and a PostgreSQL database. Make sure the backend is running before using most commands.

All commands support --json for machine-readable output — this is how Claude Code consumes them:

$ tradecraft --json health

2. Key Concepts

Screener Dormant Giant Screener

What it finds: Stocks that are "sleeping giants" — quiet before a big move. It looks for three signals simultaneously:

  • Bollinger Band squeeze — volatility has contracted, suggesting an explosive move is coming
  • OBV (On-Balance Volume) accumulation — smart money is quietly buying while price stays flat
  • Resistance breakout — price is pushing through a key level

It then verifies each candidate with EPS acceleration (earnings per share growing faster) as a fundamental catalyst. The idea: technical setup + fundamental catalyst = high-probability trade.

Best for: Swing traders looking for stocks before they break out. Scan the full S&P 1500 in one command.

Builder QuantGen Strategy Builder

What it does: Takes a natural language description of a trading strategy and generates executable Python code using VectorBT. You describe the logic in plain English, and it writes the code, backtests it, and shows you the results.

Example: "Buy AAPL when RSI drops below 30 and the 20-day SMA is above the 50-day SMA. Sell when RSI crosses above 70." → generates a complete VectorBT strategy with entry/exit logic, portfolio simulation, and performance metrics.

Key features:

  • Generates Python code using vbt.Portfolio.from_signals
  • Supports True Walk-Forward Optimization (simulates real trading — optimize on past data, trade one day at a time)
  • Multi-asset testing — run the same strategy on multiple tickers and compare
  • Lessons learned — the system remembers past code generation errors and avoids repeating them

Learning Markov Chain Trader

What it is: An AI agent that continuously learns market patterns and generates trading signals. It uses two models that retrain on a schedule:

  • XGBoost (retrains daily) — fast gradient-boosted trees on a 1-year rolling window. Good at picking up recent regime changes.
  • LSTM (retrains quarterly) — deep learning on 3+ years of data. Good at recognizing recurring multi-year patterns.

The models analyze sector ETF regimes (bull/bear market states using a statistical jump model) and generate conviction scores for individual tickers. The signal provider is injected directly into QuantGen strategies so your generated code can use Markov signals as additional filters.

Best for: Adding a "market regime" filter to your strategies. For example: "only take this trade if Markov conviction is above 0.7."

Analytics Trade Coach

What it is: Your personal trading performance analyst. It maintains a trade journal (every strategy run, every trade) and provides:

  • KPIs — win rate, Sharpe ratio, expectancy, max drawdown, equity curve
  • LLM-generated critique reports — an AI analyzes your journal and gives specific recommendations ("Your mean reversion strategies on tech stocks win 60%, but trend-following on commodities wins 80% — consider reallocating")
  • Trade CRUD — log trades manually or have them auto-logged from strategy runs

Best for: Answering "how am I doing?" with data, not gut feel.

Optimization Walk-Forward Optimization (WFO)

What it is: A backtesting methodology that simulates real trading conditions. Instead of optimizing on all historical data and testing on the same data (which overfits), WFO:

  1. Optimizes parameters on a training window (past N days)
  2. Picks the best parameters from that window
  3. Trades the NEXT day only (not the whole test period)
  4. Shifts the window forward by 1 day and repeats

True WFO goes further: position state carries over between windows (like real trading), and it steps 1 day at a time rather than in large chunks. This is the most realistic backtesting method available.

3. Command Reference

3.1 tradecraft strategy — Natural Language Strategy Lab

The flagship workflow. Describe a strategy in plain English, review the generated code, backtest it, test on other assets, and save it.

CommandDescriptionExample
strategy create Generate strategy code from a natural language description tradecraft strategy create "buy when RSI < 30, sell when > 70" --tickers AAPL
strategy review <id> Show the summary and generated code for a strategy (reads from local session cache) tradecraft strategy review a85aa5ab
strategy backtest <id> Run backtest and return full metrics (return, win rate, Sharpe, max DD, trades) tradecraft strategy backtest a85aa5ab
strategy test-on <id> --tickers Run the same strategy on multiple tickers and compare results tradecraft strategy test-on a85aa5ab --tickers MSFT,GOOG
strategy save <id> --name Save a strategy to the database for later use tradecraft strategy save a85aa5ab --name "rsi-reversion-v1"
strategy list List all saved strategies tradecraft strategy list
strategy show <name> Show a saved strategy's full details tradecraft strategy show rsi-reversion-v1

Options for create:

OptionDefaultDescription
--tickersrequiredComma-separated ticker symbols
--start-date2020-01-01Start date for historical data
--end-datetodayEnd date for historical data

3.2 tradecraft coach — Performance Analytics

Query your trade journal for KPIs, LLM-generated critique reports, and trade management.

CommandDescriptionExample
coach kpis Get key performance indicators (win rate, Sharpe, expectancy, max DD, equity curve) tradecraft coach kpis --period 90
coach report Get an LLM-generated critique with specific recommendations tradecraft coach report --period 90
coach trades list List trades from the journal tradecraft coach trades list
coach trades add Log a trade manually tradecraft coach trades add --ticker AAPL --side long --qty 100 --entry-px 150
coach trades close <id> Close an open trade tradecraft coach trades close abc123 --exit-px 160

Options: --period (days, default 90), --strategy-id (filter by strategy)

3.3 tradecraft markov — Learning Agent

Check the health of the Markov Chain Trader models and trigger retraining.

CommandDescriptionExample
markov status Show model training status, last trained dates, cached models count tradecraft markov status
markov train Trigger full retraining of all models tradecraft markov train
markov retrain-status Check retraining progress (progress %, current ticker, estimated time) tradecraft markov retrain-status

3.4 tradecraft sectors — Sector Rotation Scanner

Analyze sector ETF momentum and find leading stocks within sectors.

CommandDescriptionExample
sectors list List all 11 sector ETFs with 3m/6m performance and spread tradecraft sectors list
sectors stocks <sector> Get top stocks within a sector with technical indicators tradecraft sectors stocks XLK --limit 20
sectors ohlcv <ticker> Get OHLCV price data for a ticker tradecraft sectors ohlcv AAPL --days 150

Sector ETF tickers: XLY (Consumer Cyclical), XLP (Consumer Defensive), XLE (Energy), XLF (Financials), XLV (Healthcare), XLI (Industrials), XLB (Materials), XLK (Technology), XLC (Communication), XLRE (Real Estate), XLU (Utilities)

3.5 tradecraft screener — AI Stock Screener

Screen the S&P 1500 using technical and fundamental criteria, with optional AI multi-agent analysis.

CommandDescriptionExample
screener modes List available screening modes tradecraft screener modes
screener scan Start a screening scan (async, returns scan ID) tradecraft screener scan --mode dormant_giant --wait
screener list List recent scans tradecraft screener list
screener status <id> Check scan status tradecraft screener status abc123
screener results <id> Get scan results tradecraft screener results abc123
screener ai-report <id> Get AI analysis report (only if --use-ai was used) tradecraft screener ai-report abc123
screener delete <id> Delete a scan tradecraft screener delete abc123
screener health Check screener service health tradecraft screener health

Scan modes:

  • dormant_giant — Bollinger squeeze + OBV accumulation + EPS acceleration
  • quant_strategy — TA indicators + fundamental health + optional backtesting

Key options: --use-ai (adds AI multi-agent analysis), --wait (block until scan completes), --prompt (custom prompt for AI analysis)

3.6 tradecraft quantgen — Strategy Builder (Advanced)

Lower-level access to the QuantGen engine. The strategy command group is the recommended high-level workflow; use these for advanced use cases like running raw strategy code.

CommandDescriptionExample
quantgen generate Generate strategy code from a prompt (same as strategy create but returns raw API response) tradecraft quantgen generate --prompt "..." --tickers AAPL
quantgen run Execute raw strategy code (from string or file) tradecraft quantgen run --file strategy.py
quantgen optimize Run parameter optimization with WFO tradecraft quantgen optimize --file strategy.py --mode true_wfo
quantgen chat Chat about strategy code with the AI tradecraft quantgen chat --message "optimize this" --file strategy.py
quantgen indicators List all available technical indicators tradecraft quantgen indicators

4. End-to-End Workflow

A typical session with Claude Code looks like this:

🗣️ "Create a mean reversion strategy for AAPL" → 📝 Claude calls strategy create → 📄 Shows you summary + code
👍 You approve → 📊 Claude calls strategy backtest → 📈 Shows you metrics
💡 "Test on MSFT and GOOG too" → 📊 Claude calls strategy test-on → 📋 Shows comparison table
💾 "Save it as rsi-reversion-v1" → 💾 Claude calls strategy save → ✅ Logged to journal

Later, you can ask:

$ tradecraft coach kpis --period 90 # "How am I doing?" $ tradecraft coach report --period 90 # "What should I improve?" $ tradecraft markov status # "Is the AI learning?"

5. Learning Loops

The system has three independent learning loops that compound over time:

📝 Loop 1: Code Generation Quality

When a generated strategy fails to backtest (syntax error, VBT API misuse, etc.), the error is captured and stored in ~/.config/tradecraft/lessons.json. Before generating future strategies, relevant lessons are injected into the prompt as "known pitfalls to avoid." The system literally gets better at writing code over time.

Example lesson: "Use .vbt.gt() instead of > for VBT comparisons, and vbt.combine_logic instead of &"

📊 Loop 2: Trading Performance (Coach)

Every saved strategy run is logged to the trade journal. The Coach queries the journal to calculate KPIs and generate LLM critique reports. Over time, the Coach can identify which strategy types, sectors, or market conditions perform best for you personally.

Example insight: "Your mean reversion strategies on tech stocks win 60%, but trend-following on commodities wins 80%"

🧠 Loop 3: Signal Improvement (Markov)

The Markov models retrain on a schedule (XGBoost daily, LSTM quarterly) incorporating new market data. The signal provider serves better conviction scores over time as it sees more market regimes and patterns.

Example: After 6 months of daily retraining, the XGBoost model has learned which sector regimes produce the most reliable signals.

6. Claude Code Integration

The CLI is registered as a tool in .claude/settings.json, so Claude Code discovers it automatically:

{ "tools": { "tradecraft": { "command": "tradecraft", "args": ["--json"], "description": "TradeCraft CLI — strategy creation, backtesting, coach analytics, Markov learning" } } }

This means you can have natural conversations like:

You:

"Create a mean reversion strategy for AAPL, backtest it, and tell me if it's any good."

Claude:

[Calls tradecraft strategy create, shows you the summary and code, asks for approval, then calls tradecraft strategy backtest, presents the metrics conversationally, and offers next steps.]

The .claude/skills/tradecraft/SKILL.md file defines the conversation protocol — it tells Claude how to orchestrate the multi-step workflow, when to check lessons learned, and how to present results.

KeyDefaultDescription

$ tradecraft --backend http://other-server:8000 health
